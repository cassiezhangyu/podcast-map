# 总览旗舰页标准

总览不是目录，也不是深读页的缩略拼贴。它是全套知识包的旗舰页：依据已完成的 knowledge.md，独立讲清来源的问题、主要发现及关系、必要分支与限制。材料没有统一结论时保留分歧，不伪造唯一答案。

## 绘图前必须通过的总览证明

使用 [overview-proof.md](../templates/overview-proof.md) 写纯文本证明，并完成闭卷复述：不看深读页，仅依据该证明回答下列问题。

1. 起点问题是什么，而不是“包含哪些主题”？
2. 核心张力、变化或瓶颈是什么？材料未谈旧系统失灵时，不虚构这条故事线。
3. 哪些必要论证或相互关联的发现支撑结论？不为凑数制造三段推进。
4. 哪个具体人物、事件、物件、数据或原声让判断落地？
5. 需要保留哪些条件、反例、分歧或尚不能确定的部分？
6. 最终读者获得了什么更准确的理解、判断或仍值得追问的问题？

因理解不足无法回答时先补解读；来源本身未给答案时如实交代，不能为凑齐栏目虚构反例或行动建议。

## 信息结构

总览至少包含以下六类信息，但不要求画成六个盒子：

- 核心张力；
- 中心问题与主要发现；
- 支撑结论的必要推进或关联发现，数量由材料决定；
- 代表性来源锚点；
- 边界或失效条件；
- 最终理解、判断、选择或未解问题。

每个模块都必须承担不同功能。仅换小标题、重复同一句结论，不计为新信息。

## 核心覆盖映射

绘图前把 `source-coverage-audit.md` 中会改变全篇理解的核心语义单元逐项映射到总览。每个单元只能落入以下一种主要职责，必要时注明次要关联：

- **主关系**：推动中心问题从起点走向判断、结果或未解问题；
- **支撑系统**：解释主关系成立需要哪些方法、资源、角色、环境或约束；
- **边界与反馈**：说明何时失效、什么不能推出，以及现实结果怎样返回系统；
- **代表性锚点**：用一个足以落地的场景、数据、物件或原声支撑抽象判断；
- **深读细节**：可以从总览省略，但省略后不得改变读者对全篇主旨、因果、分歧或适用范围的理解。

如果一个核心单元只写了“见深读页”，却会改变读者对节目主旨的判断，总览不通过。映射的目的不是把所有单元平铺到一页，而是先确认没有把重要分支误当细节删掉。

## 结构选择原则

先从内容模型中找一个可以统领阅读的关系，再判断还需要哪些支撑结构：

1. **主关系给阅读顺序**：可以是循环、路径、比较、层级、张力或关系网络；必须解释知识点怎样互相作用，而不是只有编号和短语。
2. **支撑系统补成立条件**：不能被主关系自然容纳、但会改变理解的风险、环境、角色分工或并行机制，要以从属但清楚的区域接回主关系。
3. **边界与反馈完成闭合**：说明结果如何验证或修正判断，以及哪些条件下不能照搬；来源没有反馈回路时，不得虚构循环。
4. **代表性锚点负责落地**：只选择能支撑关键判断的锚点，不用大量例子挤占逻辑空间。

这不是固定版式。单线因果材料可以只有主路径和边界；多方争议材料可能采用张力图与证据分区；系统型材料可以使用核心循环和支撑层。结构必须由内容关系推出，不能照抄上一期的几何布局。

## 构图要求

- 先找统领全页的信息关系与阅读路径；因果、比较、条件或概念关系都可以成立，空间隐喻是可选手段，不强制把所有材料解释成迁移或循环。
- 关键关系组织有边界、对齐明确的阅读模块，数量服从信息归属；不能仅把若干段落等分平铺。
- 模糊文字后仍应看出入口、推进、转折和收束；但不能只剩一张大图和大片空白。
- 总览的精致度、信息量和视觉辨识度不得弱于任一深读页。
- 总览不塞入全部细节，但覆盖重要主干与必要分支。深读页补机制、证据、场景和边界，而不是补上总览遗漏的核心发现。
- 不允许用“结构很清楚”替代内容完整性：一条顺畅主线若漏掉独立风险、条件、角色或分歧，仍然失败。
- 不允许把覆盖理解成卡片平铺：核心单元应按作用归入主关系、支撑系统、边界/反馈或锚点，并在视觉上体现主从关系。

## 三候选门禁

候选数量与返修范围统一见 [production-protocol.md](production-protocol.md)。结构差异应改变阅读路径或信息归属，不以换色、框形和局部位置冒充新方案。

为每个候选写清：它最擅长解释什么、牺牲什么、最可能出现的阅读问题。选择后记录淘汰理由，再制作真实内容小样。

## 发布审查

- 三秒扫视：能否看见来源专属问题和核心关系，而不是一页平铺文字？
- 三十秒阅读：能否复述主要推进与结论？
- 独立阅读：不打开深读页，是否仍足以理解播客到底讲什么？
- 覆盖反查：每个核心语义单元是否有可见职责；被留给深读的部分是否确属不改变全局理解的细节？
- 架构审查：主关系是否给出顺序或作用机制，支撑结构是否解释其成立条件，边界或反馈是否完成判断闭合？
- 密度审查：是否有解释、锚点和边界，而不只是标签？
- 旗舰审查：与整套 contact sheet 并看，是否明显承担“精髓页”角色？

任一不通过，先回到内容模型或换构图，不用加框、缩字、填装饰来补救。
