# 稳定生产协议

新包走完整流程；定向返修复用已核验输入，只更新受影响工件，不为挪一句话重跑全套分析。

## 工件与顺序

来源核验 → 内容底账与 knowledge.md 解读母稿 → 理解验收与陌生读者改写 → 受众与发布取舍 → 页面计划与总览证明 → 视觉合同及 `palette.json` → 结构候选 → 风险小样 → 批量制作 → 最终图片朗读与审计 → 页面选择与发布。

理解记录和陌生读者预检放 content-model.md，受众、发布取舍及逐页解释桥放 page-plan.md；沿用其余来源、视觉合同、小样、审计和发布工件，不为新要求各建一份报告。决定只维护一处，其余引用。只理解内容的请求在母稿及内容检查完成后交付，不运行全套视觉工件检查。

中断后读取已有状态与输入版本，复用已验证结果；内容错误影响哪些输出才重做哪些输出。文案与图形的压缩不得静默回写成母稿的内容删减。

## 候选与风险小样

新总览考虑三个信息组织明显不同的候选；高风险深读页至少两个。候选先记录结构草案，不必全部渲染。明确读者问题、主任务、阅读路径、模块边界、容量风险和取舍；只换颜色、框形或位置不算新结构。

小样按实际风险选择，不固定 3–5 张。新包覆盖总览、最难关系或比较、最低密度或最大容量风险及封面适配；一张可覆盖多项，无须虚构人物场景来凑数。使用真实标题、正文和锚点。只修文案或线色时复验受影响页，不重做候选。

保留旧方案也是有效选择。局部试验只改变待验证关系，冻结其余变量；先完成内容与结构重设计，再调细节，不把微调当新方案。

## 页面择优是发布依据

在已有 `release-manifest.json` 增加 `selected_pages`，按最终阅读顺序记录：

```json
{
  "page_id": "overview",
  "version": "<实际版本>",
  "png": "<相对路径>",
  "editable": "<相对路径>",
  "sha256": { "png": "<实际哈希>", "editable": "<实际哈希>" },
  "status": "approved",
  "decision_basis": "<用户明确选择或最终图预检证据>"
}
```

封面以对应生成源路径替代 `editable`。用户确实批准才标 `approved`，生产者暂选用 `provisional`。不得因版本最新或脚本 PASS 升级。

最终包和 contact sheet 读取选用列表、核验路径与哈希，不遍历最新版目录。混用版本时检查页码、来源、字体和颜色角色连续性；冲突先报告或做范围明确的适配，不自动重画全套。批准资产用现有基线脚本冻结；选择记录不替代整体审查。

正式交付仍导出标准的 cover.png、infographic.png 和 series/ 序列，内容须对应选用列表。运行 scripts/check_release_artifacts.mjs 检查选用文件哈希及最终 PNG 是否来自这些选择；它不核实批准依据的真实性，也不能验证 contact sheet 实际像素，后两项必须复核。

## 返修分级

在 `revision-scope.yaml` 记录原话、页面、缺陷、根因、允许变化和冻结资产：

- L1 文案：措辞、断句，不改关系。
- L2 几何：字号、对齐、净空，不改模块。
- L3 模块：归属、层级或局部解释形式失效。
- L4 页面：平铺、主视觉失效或无入口，重新组织整页。
- L5 内容：核心判断不清或重要内容缺失，回到来源与模型。

同一缺陷连续两轮未解决才升级，不把用户择优或正常探索误判为失败。页面层无效时换结构，不继续挪字、加框、缩字。共同原语有问题需扫描全套，但扩展修改范围应明确，不以一致性改掉批准的优点。

## 验收边界

机器检查文件、几何和可测色值；最终图检查理解、密度、秩序与系列感。只看旧基准是兼容性复核，不是新规则行为验证。发布和独立审查边界见 [release-contract.md](release-contract.md)。
