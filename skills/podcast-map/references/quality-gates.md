# 质量门禁

质量检查分为机器事实、成品观察和编辑判断。三类证据不能互相替代。

## 理解验收：在排版前完成

先读 knowledge.md，再用少量代表性问题检查下列能力；按材料选择，不要求固定题数或题型：

- 复述：不用原句，能否讲清中心问题、主要发现与不可忽略的分支？
- 关系：能否解释两个知识点为何相关，区分条件、因果、先后和并列？
- 辨析：能否识别一个容易混淆的概念或看似合理的误读？
- 边界：能否指出什么不能推出，或在改变条件后原判断为何不再适用？
- 追溯：能否找到支撑关键解释的来源位置，并区分来源原话与综合？

在 content-model.md 保存问题、实际回答、来源依据与尚存缺口。错误回到相应解释或证据修复，不以语言流畅、术语数量或模型自报分数通过。生产者自行作答只算内容预检，不能声称用户理解已提升或独立盲测已通过；真实读者反馈另记，不强制每次向用户发测验。

如果用户反馈“读不懂”，先区分三种来源：原声理解遗漏、页面删掉了推理桥、或文字表达带有模板化/AI 味。不要先改颜色、字号或增加插图。

来源疑问可以保持未解；重要分支遗漏、错误归因、无依据因果和关键术语误解必须先修。与来源一致不等于事实已外部证实，核验状态需可追溯。

## 陌生读者与自然语言预检：在排版前和最终图各做一次

按 [reader-first-writing.md](reader-first-writing.md) 检查去语境复述、整套节奏和最终图片朗读。排版前检查解释是否完整，最终图检查删改、断行和视觉顺序有没有重新制造理解缺口。

- 遮住节目名、人物名、页眉和来源栏后，正文仍能说明问题、关键关系和必要边界；
- 人物身份、术语、代词和案例第一次出现时有足够上下文，不要求读者听过原节目；
- 连读全套标题、分区标题和收束句，没有因写作惯性反复出现同一种否定对偶、三段式或口号式结尾；
- 具体处境、动作和条件承担解释，抽象词不代替推理；
- 页面精简后仍保留母稿中的关键推理桥，不靠下一页补当前页的前提。

这些项目需要编辑判断，不能由敏感词计数或模型自报 PASS。单个对偶、三点并列或抽象术语可以合理存在；问题在于它是否贴合内容、是否造成跨页机械重复。没有独立读者时只标“生产者陌生读者预检完成，独立理解验证未执行”。

## 1. 机器事实

直接从最终文件和可编辑场景推导：

- 交付文件是否齐全、页数是否配对；
- 画布尺寸和背景；
- 文字、形状和线路是否越界、碰撞或裁切；
- 正文字号、标题层级和来源可读性；
- 页码是否存在、连续且位置一致；
- PNG 与可编辑源是否来自同一版本；
- 本轮是否对所有发生文字、换行、字号或模块尺寸变化的场景重新导出并扫描，而不是只检查被批注的一页；
- 封面实际 SVG 是否符合 [cover-design.md](cover-design.md) 的固定组件；未接入检查的旧稿不能宣称封面合规。PNG 同步和标题视觉层级另看最终图，不由文件尺寸推定。

新包另运行配色审计，核对场景实际颜色是否来自唯一 palette.json、白底和基础文字对比度。脚本不会判断色彩语义、嵌入图片或最终叠加效果，封面也须看最终图。

脚本只能对这些事实给出 PASS。它不得因为 JSON 中写了 `true`，就宣称来源指纹、解读深度、视觉必要性或阅读节奏通过。

## 2. 成品观察

先只看最终 PNG 和 contact sheet，不读取 `page-plan.md`、`quality-audit.md` 或拓扑声明。

发布审查必须由一个不依赖生产解释的观察上下文执行；若只能由生产者完成，明确标为“最终图视觉预检”，不能冒充独立红队。审查先记录盲看结论，再对照内容模型。

### 总览

- 能否不打开组图，复述中心问题、主要发现及关系、代表性证据、重要分支与边界？
- 它是否解释了关联或分歧，而非只有带编号的目录？多主题材料不强求统一结论。
- 视觉入口是否明确，次要信息是否服从主干？
- 与全部深读页并看时，它是否在信息覆盖、结构辨识和完成度上承担旗舰角色，而不是较弱的目录页？
- 三十秒阅读后，是否能回答“来源到底在讲什么”，而不需要深读页补核心结论？

### 单页

- 页面标题是否提出了具体判断或问题？
- 隐藏标题和来源栏后，是否仍能看出属于该来源的场景、术语或矛盾？
- 主视觉删除后，是否会损失某种具体关系理解？
- 正文是否承担解释，而不是为了数字阈值堆字？
- 页面是否存在空容器、未解释死区、线路骑字或只有放大才能阅读的内容？
- 三秒扫视是否已经给出“为什么值得读”的入口，而不是只有读完小字才知道页面内容？
- 第一次接触材料的读者能否只靠本页理解标题中的对象、正文里的代词以及图形各部分为何相连？
- 除标题外，是否有足够解释、证据或关系支撑阅读？稀疏示意不能独立撑页，但不强制上中下三段布局。

### 整组

- 最弱三页是哪三页，为什么？
- 连续页面的重复形式是否由相同阅读任务解释，还是不同内容被迫套用相同入口、主图位置和底部大框？
- 模糊文字后是否仍看得出分区与信息重量？不把每页轮廓不同当成硬指标。
- 阅读顺序是否逐步改变读者模型，而不是并列展示主题？
- 标题、分区标题和收束句连读时，是否因相同句型、固定三段式或强行升华而显得机械？
- 视觉变化是否来自内容关系，而不是换色或改变拓扑名称？
- 总页数是否能由内容厚度解释？逐页执行合并测试后，是否仍有页面可以无损并入相邻页？
- 缩略图是否让人感到“内容丰富但可进入”，而不是“空、薄、像草图”或“满、挤、无法开始”？
- 白底、颜色角色、页眉进度和单线页脚是否遵守 `visual-contract.yaml`，且任何例外都有理由？
- 新包选色是否查看了近期不同来源，而不是把同集多个版本算多套？强调色是否确有职责，是否又被删成全黑？封面和正文是否同源取色？
- 选用列表是否对应用户实际选择、准确文件和哈希，而非默认最新版？混用版本是否维持系列连续性？

### 手机尺寸

至少以约 360–430 CSS px 宽度查看每张最终图。记录：最小正文是否无需放大可读、模块内部是否能按预期顺序阅读、颜色是否仍能区分语义、线条是否压住字形。原尺寸通过不能替代手机尺寸通过。

## 3. 编辑判断

对照解读母稿、内容模型和发布取舍，核对成品是否兑现：

- 来源区段是否有合理覆盖；
- 来源主张、编辑综合和延伸是否区分；
- 关键结论是否有条件和边界；
- 每页的不可替代贡献是否实际可见；
- 相邻页是否重复同一结论；
- 最终出口是否从整套论证长出。
- 图片是否删掉母稿中会改变判断的条件、重要异议或说话人归属？
- 专题摘编是否明确范围？默认全篇总览是否仍覆盖来源的重要主干？
- 文案是否面向预设读者解释必要术语，而非依靠其听过原节目？
- 公开小红书正文是否可独立阅读、没有页码/文件名/节目串场，且只使用少量相关话题标签？

## 4. 信息密度诊断

字符数是异常探测器，不是质量分数。

- 文字显著少：检查是否只有口号、标签或空白；
- 文字显著多：检查是否存在段落堆积、字号下降或图形失效；
- 与正面基准差异较大：解释是内容类型所需，还是质量退化。

不要设置所有页面必须达到同一字符数。关系图、场景页和编辑叙述页可以有不同密度，但都必须在正常手机宽度下提供足够回报。

### 密度与页数联合诊断

不要单独问“这一页够不够满”，而要同时问：

- 这页独立后增加了哪一种相邻页容纳不了的理解？
- 它是否包含至少一个完整解释链、一个丰富场景，或一组形成新理解的证据并置？
- 若把它合并到相邻页，手机可读性和主视觉是否真的恶化？
- 若答案是否定的，减少页数；不得用放大留白、拆分短句、增加装饰或通用框架挽救页数。

信息密度的目标是单位页面有足够认知回报，同时保留进入路径。白色面积本身不是问题；没有承载停顿、对照、关系或场景的空白才是问题。

## 5. 视觉必要性

每个主图执行删除测试：

1. 隐藏图形，只保留文字；
2. 说明损失的关系理解、比较效率、信息归属或来源场景信息；
3. 若图形不改善理解或阅读效率，删除或重做；矩阵能降低寻找对应项的成本，就不属于纯装饰。

叙事、人物和反思页面可以用编辑构图形成视觉理解，不强制复杂逻辑图。

## 6. 基准比较

查看 [benchmarks.md](benchmarks.md) 中适用的正面和反面基准。逐项写明新作品持平、更强或更弱的证据。

不得写“已达到 v20”“视觉多样”之类无页面证据的结论。至少引用具体页面、可见关系和来源锚点。

根据实际风险选择适用基准，不为局部返修重看所有历史套图。skill 变化的验证层级见 [rule-regression.md](rule-regression.md)；只查看旧稿不能证明新规则的行为效果。

## 7. 返工顺序

失败时按以下顺序处理：

1. 内容判断；
2. 页面贡献与顺序；
3. 表达类型和主视觉；
4. 页面结构；
5. 文字编辑与断行；
6. 几何、线路和字号；
7. 配色与细节。

不要用缩字、补卡片或改审计文字修复上游问题。
