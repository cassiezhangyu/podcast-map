# 页面编辑：先阅读任务，再选形式

题材决定哪些证据必须保留；阅读任务决定如何组织证据。人物内容也可能需要矩阵，技术内容也可能需要场景。不要从组件库或题材标签反推布局。

## 阅读任务选择

先在 page-plan.md 用一个简短的“发布取舍”段记录：目标读者及已有知识、传播切口、解释重点、仅保留在 knowledge.md 的细节与原因。受众未知时使用内容模型中的默认假设，不重新询问；切口服务进入，不改写来源立场。

理解稿覆盖重要主线、分支与分歧；发布稿可以选择细节，但不能删掉会改变判断的前提或反例。默认全篇总览仍交代来源所有重要主干，深读页可有所侧重。只有用户明确要求专题摘编时才缩小覆盖范围，并在公开标题或副标题自然说明范围，不把局部称作全篇解读。

| 读者任务 | 可能有效的组织方式 | 需要证明的价值 |
|---|---|---|
| 比较选择、判断或前后差异 | 共同维度的矩阵、并排对照 | 对应项容易找到，减少寻找与记忆负担 |
| 追踪变化、因果或反馈 | 路径、循环、状态变化 | 每步为何导致下一步，方向和边界明确 |
| 理解资源、价值或责任交换 | 关系地图、带标签的流向、分层关系 | 谁给谁什么，哪里受阻，如何返回 |
| 理解空间、几何、动作和尺度 | 剖面、示意、局部放大、同尺度对照 | 单靠段落难以看出的形态差异变直观 |
| 理解人物处境和选择代价 | 场景、证词并置、时间转折、判断矩阵 | 保留具体人、事、语气和限制 |
| 辨别概念、前提和边界 | 对照、条件分支、编辑论证 | 不把相关画成因果、价值判断画成数据 |

这些是候选，不是模板菜单。多个任务同页时确定主任务，次要解释从属；互相争夺入口且手机无法承载时才拆页。

## 页面卡

在 `page-plan.md` 为每页记录以下内容，可用紧凑表格，不要求各字段独立成节：

```text
page_id:
reader_before / reader_after:
reading_task:
indispensable_contribution:
knowledge_units:
source_anchor / claim_class:
relation_or_tension:
expression_mode / visual_necessity:
boundary_or_implication:
neighbor_dependency / merge_candidate:
scan_hook / density_plan / capacity_risk:
```

- 认知变化不是“知道更多”，而是能比较、解释或判断什么。
- 不可替代贡献说明：删除或并入相邻页会损失什么必要理解？
- 视觉必要性包含比较效率和信息归属，不只包含因果；矩阵不必创造文字以外的新事实才有价值。
- 扫读入口具体，正文承担解释；不要只有大标题和抽象名词。
- 密度计划描述分区与回报，不强制上中下三段或统一模块数。

## 页数与顺序

按 [density-and-visual-translation.md](density-and-visual-translation.md) 聚合单元并验证容量。先做最少可行页组，再说明拆页理由；深读最多 15 页，无最低页数。不能由播客时长、话题数量或参考套图数量直接推算。

独立关系、不同边界、争夺入口的主问题，或正常手机字号无法共存，可以成为拆页理由。互相解释的薄观点应合并；丰富场景或完整机制可以独立。

顺序服务理解，不必复制来源时间线。总览覆盖主干，深读补机制、证据和边界，不逐页复述总览标签。

## 候选与版本选择

候选及小样要求见 [production-protocol.md](production-protocol.md)。比较新旧时同时看新增理解和失去的清晰度。若新图让对应项更难找到，保留旧矩阵；若新关系图让交换方向更清楚，可以替换旧排列。

同一种形式可以重复，只要这些页确实承担同一种任务。要拦截的是内容被迫迁就骨架，不是相似对齐线；不为布局多样性降低可读性。
