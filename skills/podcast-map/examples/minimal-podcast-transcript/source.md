# 示例播客转写：先画地图，再选择路线

**00:00–00:34 主持人：** 团队常在会议上争论应该立刻做功能，还是继续研究用户。两种意见听起来相反，但我怀疑大家担心的其实不是同一件事。

**00:35–01:14 嘉宾：** 快速做功能可以验证使用行为，可如果连用户问题都没说清，功能反馈也可能无法解释。继续研究能减少误判，但研究没有停止条件，也会推迟真实反馈。两条路线对应的是不同风险。

**01:15–01:59 嘉宾：** 与其固定选择一边，不如先写出当前最不确定的判断。不确定用户是否真有这个问题，就先访谈和观察；问题反复出现、但不知道哪种方案可用，就做最小原型。每轮开始前写明要减少哪一种不确定性，结束时根据证据决定继续、调整还是停止。

**02:00–02:07 主持人：** 这样就能保证产品成功吗？

**02:08–02:36 嘉宾：** 不能。它只让团队知道自己正在验证什么，也让失败更容易解释。时间极短、风险极高或必须遵守强制规范时，还需要其他决策机制。
